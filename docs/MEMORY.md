- fly deploy: always pass `--ha=false` on first deploy — default creates 2 machines, which breaks in-memory `slowapi` limits (needs exactly one instance).
- `ALLOWED_ORIGIN` in `fly.toml` `[env]`, not Fly secrets: public value, versioned with deploy config; secrets reserved for keys/tokens.
- `/health` liveness only, no DB ping: Fly checks every 30s would keep Neon awake and burn free compute hours.
- test client dep is `httpx2`, not `httpx`: Starlette's `TestClient` deprecates `httpx`.
- config via plain `os.environ`, no pydantic-settings: `KeyError` already names missing var; add settings lib only if typed parsing/validation gets real.
- chat model call: `thinking: disabled` + `effort: low` on Haiku 5.5 — thinking is on by default and eats the 600-token `max_tokens` budget meant for visible text; revisit when tools land (S08).
- `refusal` stop → error frame: Haiku 5.5 has no server-side refusal fallback, so stream must end with a readable message instead of silence.
- `/chat` catches broad `Exception` inside the SSE generator: HTTP 200 + headers already sent, so any failure must surface as a `{"error"}` frame, never a dead stream.
- Fly secrets set via `grep '^KEY=' .env | fly secrets import --stage` then `fly deploy`: value never printed, one restart.
- tests set env in `tests/conftest.py`: `app.config` reads env at import, so env must exist before any app import.
- rate limit key `Fly-Client-IP` is trustworthy: Fly proxy overwrites a client-supplied header (verified live: spoofed value still hit same counter).
- 429 retry seconds read from `limiter.limiter.get_window_stats(...).reset_time`, not slowapi's default handler: default body leaks limit string ("10 per 1 minute") and has no human retry time.
- fixed window accepted over moving window: allows ~2× burst at window boundary; daily budget cap (S14) is real spend backstop.
- tests fake clock by monkeypatching `time.time`: `limits` in-memory storage and the 429 handler both read `time.time()`, so one patch moves windows and retry math together.
- CI deploy token expires 2027-10-22 (`fly tokens create deploy -x 8760h`): rotate by piping a new one into `gh secret set FLY_API_TOKEN`; expired token shows as deploy step auth failure.
- deploy `concurrency.cancel-in-progress: false`: cancelling mid `flyctl deploy` can leave a half-rolled machine; queued runs still collapse to newest.
- changed-file detection is a shell `case` over `git diff`, not a paths-filter action: no third-party action with repo access; unknown `before` (first/force push) deploys rather than silently skipping.
- action pins ≥2 weeks old (`setup-uv@v10.2.0`, not same-day `v10.3.2`): fresh releases are where supply-chain compromises land.
- ingest embeds all changed chunks in one batched Voyage call: account without payment method returns 429 after ~3 requests/min (hit live with per-file calls); add payment method if knowledge grows past 128 chunks per run.
- ingest wraps migration + embedding + writes in one transaction: Voyage failure mid-run (live 429) left DB untouched; embedding inside txn holds it open briefly, fine for a manual CLI.
- `messages.id` is uuid, not bigserial: S13 feedback receives `message_id` from the browser, so ids must not be enumerable.
- run ingest as `python -m scripts.ingest`, not `python scripts/ingest.py`: script-path mode puts `scripts/` on sys.path and `import app` fails.
- psycopg pool `prepare_threshold=None`: Neon pooled URL is PgBouncer transaction mode, prepared statements break across pooled connections.
- pool `timeout=5`: default 30s made visitors wait 30s for a 503 when Neon unreachable (measured live); 5s still covers a Neon cold-start wake.
- empty assistant replies never saved: API rejects empty assistant content, so one empty row would break every later turn of that chat.
- `start_turn` before `StreamingResponse`: refusals (turn cap 429, DB 503) need real status codes, impossible once SSE 200 headers are sent.
- local dev `.env` points at the same Neon DB as prod: local test chats land in prod tables; clean up or use a Neon branch before analytics (S18) matter.
- retrieval floor `MIN_SIMILARITY = 0.25`, not 0.3: live stubs gave relevant best hits 0.28–0.51 vs off-topic ≤ 0.20; 0.3 dropped "What is his education?". Whole-file stub chunks dilute scores — retune on real KB (M5).
- citations parsed from `[n]` markers in final text, not "all retrieved docs": lists only sources the answer actually used; matches groundedness eval (S16).
- Haiku with thinking off sometimes writes a preamble ("I'll check…") before tool calls despite prompt rule; kept (paragraph-break join) — track in evals (S16) rather than enable thinking.
- tool `eager_input_streaming` off: single short `query` string, buffering costs nothing; input still validated before search.
- text before first tool call held back, dropped if a tool follows: with thinking off, Haiku narrated plans into the reply ("Polish question, so CV language is pl") and repeated answers (seen live). Cost: replies with no tool call arrive in one frame; post-tool answers still stream.
- tool notes say "already shown" on repeat card calls: model otherwise claimed "each shown twice" while cards were deduped.
- Haiku still says "above/below" for buttons despite prompt rule; position depends on widget (S10) — track in evals (S16).
- public config (CALENDAR_URL, CV_URL_*) stays in `fly.toml [env]`, not secrets (user decision): reviewed in git; changes deploy via CI.
- emails redacted before storing messages, model sees current message raw: architecture forbids emails in Postgres; cost is an email from an earlier turn must be asked again (redacted in history).
- GitHub failure tool note says 'button already shown, call no other tool': live, the model re-called book_call and wrote the apology twice.
- `mark_escalated` failure after issue created → still report ticket: otherwise visitor sees error and retries into a duplicate issue.
- accepted risk: one ticket per chat means a spammer can open one issue per new chat, bounded only by 60 msgs/day per IP; add per-IP daily escalation cap if the handoff repo gets noisy.
- `answer` row whenever tokens were spent, `message_id` null on failed reply: daily budget (S14) sums `cost_usd`, so failed/refused replies must count; resolution metrics (S18) must filter `message_id is not null`.
- `rate_limited` exception handler is async: Starlette runs sync handlers in a threadpool where `asyncio.create_task` has no running loop.
- `first_token_ms` ≈ `latency_ms` on replies without tool calls: text before first tool call is held back (S09), so it arrives in one frame at the end.
- validation runs write test rows into prod `events`/`conversations` (local .env = prod Neon); exclude or delete before `/insights` (S18) numbers matter.
